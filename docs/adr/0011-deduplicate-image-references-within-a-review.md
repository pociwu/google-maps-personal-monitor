# 依評論與圖片內容去除重複引用

Google 可能以不同來源網址重複提供同一則評論的相同圖片，也可能重新壓縮圖片，使檔案位元與解碼像素都略有差異。系統依序比較下載內容 SHA-256、EXIF 方向校正後的精確 RGBA 像素 SHA-256，以及嚴格的有損重編碼規則。最後一層只接受同尺寸 JPEG、WebP 或 AVIF，並同時要求 256 位差分雜湊距離及 64px RGB 平均與均方根誤差低於固定門檻。

永久原圖仍依原始檔 SHA-256 保存，跨評論引用相同內容時各自保留關聯。感知比對不得單獨依賴雜湊，也不套用於 PNG 等無損格式；尺寸不同或任一誤差門檻未通過時仍視為不同圖片。

部署在清理既有引用前必須先建立 SQLite 備份，輸出掃描及刪除筆數；清理失敗時中止部署並保留原版本。後續巡查在圖片保存完成時立即套用去重規則。

評論的圖片數量及圖片修改判定使用去重後的原始檔 SHA-256 代表集合。僅 Google 來源網址或通過嚴格規則的重新編碼版本增減不產生修改事件；唯一圖片內容真正新增或移除時才依既有規則通知，已永久保存的原圖不因目前集合移除而刪除。

圖片移除需連續兩次完整且圖片保存無失敗的巡查才能確認；新增圖片成功保存後立即生效。Telegram 修改通知只列出新增與移除數量，不重新發送整批圖片。

舊資料遷移時，去重後留下的既有唯一圖片全部先視為目前圖片；不根據缺乏狀態的歷史資料猜測圖片已移除，後續再由兩次完整缺失規則逐步校正。
